# 安全与合规 · security.md

> 本文介绍项目的安全设计、隐私保护，以及**这个展示仓库**的公开边界与微信平台合规说明。

## 1. 身份与认证安全

| 措施 | 实现 |
| --- | --- |
| openid 不落明文 | 用户 ID = openid 的 HMAC-SHA256 派生值（`wx_` 前缀），数据库脱库也无法还原 openid |
| openid 存档加密 | 需要发送订阅消息时必需的 openid 以 AES-256-GCM 加密存储 |
| 无状态令牌 | HMAC-SHA256 签名（7 天有效），校验为常量时间比较，防时序侧信道 |
| 管理员鉴权 | 独立于用户令牌的 `X-Admin-Key`；支持具名密钥（操作者身份由服务端推导，不信任自报）；常量时间比较 |
| 游客模式 | 仅本地开发可用，云端强制禁用 |
| 内嵌管理页 | 仅服务器回环地址（loopback）可访问，带 CSP 与 X-Frame-Options: DENY |
| 密钥纪律 | 密钥只经环境变量注入；`.env*` 全部被 git 忽略（历史核查确认从未提交过敏感文件）；部署脚本对输出日志实时脱敏 |

## 2. 内容安全

- **先审后发（fail-closed）**：全部用户自由文本（评论、自定义申请、投票理由、后续、昵称）必须先过微信 `msg_sec_check` v2；审核接口未配置或调用失败时**拒绝发布**（503），绝不放行；检测存疑转人工复核；
- **人工优先**：管理员复核结论永不被自动流程覆盖；自动通过的内容仍可被复核隐藏；
- **社区自治**：3 人举报自动隐藏转人工；举报按用户去重、独立留痕；
- **结构约束**：评论限 2–100 字、禁链接 / @ / 换行；请求体 4KB 上限 + 未知字段拒绝；头像 512KB、文章 64KB 单独限额——从入口压缩攻击面；
- **编辑内容合规**：文章为运营内容，上架动作即运营者人工合规确认，全部操作留追加式审计记录。

## 3. 隐私保护与用户权利

- **最小化收集**：无手机号、无第三方 SDK、无埋点统计 SDK；唯一身份材料是微信登录 code 换取的 openid（加密处理如上）；用户头像 / 昵称为用户主动设置；
- **用户权利通道**：小程序内直接提交查阅 / 更正 / 删除 / 注销 / 申诉五类请求，管理员在后台处理并回复，全程可查进度；删除类请求驳回时必须给出理由；
- **权限分级**：申请人对自己的申请有「补后续」等专属操作；评论作者只能删自己的评论；游客只能读公开内容；
- **数据可携**：内置备份 / 恢复工具（SHA-256 校验和、空库保护、一致性快照事务）支持运营者对数据安全地导出与恢复。

## 4. 防滥用与限流

| 风险 | 对策 |
| --- | --- |
| 刷投票 | 每人每申请一票（主键约束）+ 每日 20 票 + 单申请 21 票封盘 |
| 刷申请 / 刷评论 | 同时进行 5 份上限 + 每日 20 份 + 每日 10 条评论 |
| 重复举报 / 报复性举报 | 举报按 (举报人, 评论) 主键去重；不能举报自己 |
| 深翻页爬取 | 广场 keyset 游标分页 + 无公开批量导出接口 |
| 内容量攻击 | 请求体大小限制、字段白名单（DisallowUnknownFields）、文本长度与格式校验 |

## 5. 展示仓库的公开边界

本仓库（can-i-take-a-break）是**公开展示仓库**，遵守以下边界：

- **不包含业务源码**：小程序与 Go 后端的开发仓库独立私有维护，此处只有文档、截图与展示页；
- **不包含任何配置值**：微信 AppID / AppSecret、云托管环境 ID、服务名、MySQL 凭据、管理密钥一律不出现（文档中以「开发仓库的环境变量」指代）；
- **不包含用户数据**：不含数据库导出、备份文件、日志；截图均为开发阶段演示数据；
- **不含内部地址**：不出现服务器 IP、内网域名、云环境标识；
- 发布前应核对敏感信息（见 [SECURITY.md](../SECURITY.md) 的扫描范围说明）。

## 6. 微信平台合规边界（重要声明）

本产品涉及用户发布内容（UGC）与公开评论，属于社区互动形态。如实区分三层：

| 层 | 现状 |
| --- | --- |
| **技术能力** | 内容安全审核、举报、申诉、审计、隐私请求等社区治理所需的技术能力**均已实现并有测试** |
| **当前开放状态** | 小程序以**体验版**运行（面向指定体验成员），未对公众开放；订阅消息功能整体关闭 |
| **展示方式** | 核心功能已完成。由于个人主体在社交互动类目上的准入限制，目前通过体验版展示与收集反馈。 |

体验资格由开发者管理；未来如调整主体或服务范围，将按对应的平台准入要求推进。

## 7. 已知安全取舍

- 密钥依赖环境变量与云托管容器的安全，未引入 KMS 类服务（个人项目量级的取舍）；
- 自动审核无重试队列，审核接口瞬时故障会拒绝该次发布（fail-closed 的代价，用户可重试）；
- 备份为手动 CLI，无定时任务（见 [roadmap.md](roadmap.md) 规划）；
- 全局写序锁防并发，但意味着写路径不设计为多写节点水平扩展。

以上取舍均为**已知并记录**，不属于疏漏；对应讨论见 [backend.md](backend.md)。
