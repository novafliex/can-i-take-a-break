# 产品文档 · product.md

> 「今天能摆吗？」是一款以日常情绪表达、趣味投票和轻量互动为核心的微信小程序。它给疲惫的日常一点幽默。

## 1. 问题观察

大学生和年轻职场人的日常里，充满了一种「不值得认真纠结、但确实会纠结」的小事：

- 今晚有个饭局，其实只想回家躺着；
- 购物车里躺了很久的东西，下单又犹豫；
- 编辑了很久的消息，不知道该不该发出去。

这类小纠结的共性是：**认真权衡显得小题大做，闷在心里又有点可惜**。它们需要一个出口——不是建议、不是说教，而是有人陪着认真一下。

## 2. 产品定位

把日常小纠结写成一份「申请」：选个主题（或自定义）、讲讲理由、定个 15/30/60 分钟的时限，然后让路人们投票「批准 / 驳回」。

核心主张：**产品不是替你决定该不该摆，而是让「想摆一下」变得有趣。**

- 投票是社交互动，不是现实许可，结果不具任何约束力；
- 产品是轻社交娱乐，不是审批系统，不鼓励逃避责任；
- 产品也不是心理疏导平台，不提供任何专业支持。

### 与常见形态的差异

| 常见形态 | 本产品的不同 |
| --- | --- |
| 投票工具 / 表决系统 | 投票对象是生活小事，体验重心是趣味与共鸣，不是效率与权威 |
| 树洞 / 心理社区 | 不收集痛苦叙事，不提供专业支持，内容以幽默短申请为主 |
| 决策助手 | 刻意「不智能、不严肃」，过期自动结算，平票就是「未形成有效结果」 |

## 3. 目标用户与场景

**目标用户**：学生与年轻职场人，熟悉表情包与梗文化，喜欢轻互动、低社交压力的表达。

**典型场景**：

| 场景 | 用户动作 | 获得什么 |
| --- | --- | --- |
| 下班/下课后瘫着，纠结要不要参加活动 | 发起「今晚能不去吗？」申请 | 看到陌生人为自己盖章，玩笑式地「被批准」 |
| 学习/工作疲惫，想休息又有点愧疚 | 发起或围观「今天能摆吗？」 | 从别人同样的理由里获得共鸣 |
| 睡前刷手机 | 在广场看别人的申请与后续故事 | 轻松的内容消费，「原来大家都这样」 |

## 4. 核心价值与设计原则

**核心价值**：用轻松、克制而友善的方式，让普通生活多一点幽默与共鸣。

体验设计上遵循几条原则（均已落实到产品机制）：

1. **先看懂，再参与**——首页直接呈现产品主张与热门内容；投票页是抽卡式的单张浏览，不用先理解规则。
2. **低社交压力**——没有关注关系、没有私信；投票匿名于申请人（申请人看不到谁投了什么）；评论先审后展示。
3. **结果轻量化**——申请限时结算（15/30/60 分钟），到期自动出结果；票数不足 3 票或平票一律显示「未形成有效结果」，绝不显示「50% 赞同」这种伪精确数据；投票中的申请不显示赞成比例，避免带节奏。
4. **克制的成长系统**——投票 +5 XP、与多数派一致 +3 XP、后续表态 +1 XP，等级只是趣味称号，没有排行榜。

## 5. 产品关键词与语言纪律

产品关键词：日常表达、趣味投票、轻量互动、幽默与共鸣、真实生活、友善交流。

为了保持「轻松但不轻浮」的语气，产品文案有明确的语言纪律：

- 使用「申请 / 投票 / 批准 / 驳回 / 大家的看法」这类游戏化但中性的词；
- 刻意避免「民间审批局」「局长」「权威裁定」等机构化、授权化措辞——那会把玩笑变成角色扮演，偏离「幽默」的初衷；
- 不说教、不制造焦虑；平票的表述固定为「未形成有效结果」。

## 6. 内容边界

产品对内容有清晰的负面清单，并由技术手段兜底（详见 [security.md](security.md)）：

- 不碰自伤、违法、重大财务或医疗决定类内容——自定义申请文案必须先通过微信内容安全检测；
- 评论区先审后发（fail-closed），3 人举报自动隐藏转人工复核；
- 编辑部内容（「聊两句」文章）全部为原创生活观察，标注「今日编辑部」来源，不冒充真实用户，不评论社会事件。

## 7. 衡量与现状

产品设计上关注「参与深度」而非「规模指标」：申请的参与人数、评论互动率、后续故事线的追加率。产品当前处于体验版阶段，未公开上线，因此**不设任何用户量、留存率类宣传数字**。

真实的功能完成状态见 [features.md](features.md)；当前阶段与平台合规边界见 [security.md](security.md)。
