## 2. 主流程：发起一次申请（摆一下）

1. **进入首页**：静默登录（首次请求 401 时自动 `wx.login` 换取令牌，用户无感知）；首页展示品牌区、今日精选、文章卡与「我的申请」。
2. **展开表单**：三步——① 主题：6 个预设（今天能摆吗 / 这钱能花吗 / 今晚能不去吗 / 这顿能吃吗 / 这话能发吗 / 这决定能做吗）或自定义标题（2–24 字，需过内容安全审核）；② 理由：预设理由或自定义（6–100 字）；③ 时长：15 / 30 / 60 分钟。
3. **提交**：先在点击手势内请求订阅消息授权，再提交；同一时间最多 5 份进行中的申请，超出会得到明确提示。
4. **提交后**：跳转申请详情页，立即分享给投票 tab 的待投队列。

**约束**（均由服务端强制）：24 小时内最多提交 20 份申请；「今天能摆吗」主题的截止时间不会跨过东八区凌晨 4:00（「摆烂日」以凌晨 4 点为界）。

## 3. 主流程：投票（看热闹的参与侧）

1. **抽卡浏览**：投票 tab 每次呈现一份可投申请（`GET /applications/pending?skip=` 支持跳过最近看过的 20 条）；支持上一条/下一条回看历史（最多 30 条）。
2. **投票**：批准 ✓ / 驳回 ✕，可选附一句理由（理由会以「立场评论」形式进入评论区，并可能成为神评论）；自己不能投自己的申请。
3. **两阶段投票**：
   - **正式投票**（截止前）：计入 `批准/驳回` 计数，单份申请满 21 票封盘；每人每份申请只能投一次；
   - **后续表态**（截止后 7 天互动期内）：写入独立的「后来的人怎么想」计数，**不改变已锁定的结果**；前端按服务端返回的阶段区分展示（投票 +5 XP / 表态 +1 XP）。
4. **每日限额**：24 小时内最多投 20 票（跨申请累计，防刷）。
5. **结算规则**：到期自动结算——有效票不足 3 票或平票 → 「未形成有效结果」；否则多数派胜出。结算幂等，重试不会重复计入。

## 4. 申请详情页（档案页）

- 档案抬头：编号、状态印章（已批准 / 已驳回 / 未形成有效结果）；
- 比例条：投票中保密显示（避免带节奏），结束后展示比例与「默契度」（你的选择与多数派是否一致）；
- 神评论：点赞最高的评论置顶展示；
- 「后来的人怎么想」：截止后的表态比例（独立于正式结果）；
- 「后续来了」：申请人追加的后续故事线，最多 5 条，时间线展示；
- 评论区：最热 / 最新排序、批准派 / 驳回派立场筛选、两级楼中楼、点赞、举报、删除自己的评论、对被拦截评论的申诉入口；
- 上一条 / 分享 / 下一条导航。

## 5. 广场（看热闹的浏览侧）

- 双频道：「申请广场」（全部 / 投票中 / 已结束筛选）+「聊两句」文章流（今天在聊 / 人间观察 / 离谱研究所三个栏目筛选）；
- 申请卡：状态标签、「有后续」角标、倒计时、参与人数；
- 分页：keyset 游标（`next_cursor`），上拉加载更多，翻页不重不漏；
- 文章卡：封面、栏目、讨论数；封面加载失败自动回退纯文字样式。

## 6. 文章「聊两句」

- 阅读页：栏目、日期、标题、导语、来源（统一为「今日编辑部」）、正文、文末话题；
- 评论：与申请评论共用同一套审核 / 点赞 / 举报 / 删除 / 申诉链路；
- 转化闭环：「我也申请一下」带着文章上下文跳回首页表单，发布成功后申请详情页会展示「来源文章」并可回跳。

## 7. 我的

- 身份卡：头像（微信头像或系统预设）、昵称、等级称号与 XP 进度、三项统计（参与投票 / 后续表态 / 多数一致）；
- 我的记录：「我发起的 / 我参与的」两组列表，可按全部 / 投票中 / 已结束筛选，分页加载；
- 最近动态：聚合展示（默认 2 条，可展开）；
- 外观：三套主题（clean / retro / fun）即时切换，原生导航栏与 tabBar 一并换肤；
- 编辑资料：昵称、微信头像或系统头像；
- 入口：隐私与申诉、参与说明、管理中心（隐藏入口）。

## 8. 隐私与申诉

- 五类请求：查阅 / 更正 / 删除 / 注销 / 内容申诉，提交时需勾选确认；
- 从详情页对被拦截评论发起申诉时，自动带入目标评论 ID；
- 我的处理记录与我的举报记录查询；
- 在线客服入口。

## 9. 管理中心（小程序内）

- 鉴权：输入管理密钥，经 `X-Admin-Key` 头调用管理接口；离开页面即清空密钥，不落本地存储；
- 待办总览：待处理请求 / 内容举报 / 待审核评论 / 已处理记录四格；
- 请求处理：按状态筛选，执行「处理中 / 已完成 / 未通过」流转并附处理说明；申诉 / 删除类请求会先核验关联评论现状，支持「恢复评论并完成 / 删除评论并完成 / 驳回申诉维持拦截」联动操作；
- 评论复核：待复核 / 被举报 / 已拦截三组，批准发布或隐藏；
- 每步管理操作在服务端追加审计记录，业务接口不提供修改或删除（操作者由密钥在服务端推导，不信任自报）。

另有 Web 管理页（服务端内嵌，仅限服务器本机回环地址访问）提供评论复核与文章管理面板。

## 10. 内容运营（编辑部侧）

- 预设内容三档：18 条基础演示申请（常驻）、15 条轮换选题（90 分钟时间槽，任意时刻恰好 5 条「值守」可投）、33 篇编辑部文章（6 篇示例常驻上架 + 27 篇草稿按运营节奏人工上架）；
- 全部补种幂等：已存在的运营改动不被覆盖；演示内容与真实用户数据隔离，演示数据不计入任何真实指标；
- 上架动作即运营者人工合规确认（文章不走机器审核，由人负责）。
