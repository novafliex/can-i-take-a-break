小纠结，也值得被回应

核心让一个人的小情绪，成为大家参与的小故事

有些想法不容易郑重其事地说出口。「申请摆烂」给表达加一点幽默，让疲惫和犹豫有一个轻松的开场。一次投票是回应的起点，讨论和后续让交流继续发生。

01

用申请，说出小情绪

想休息一下、想拒绝聚会，或者只是有点纠结。选一个生活主题，写下理由，把原本闷在心里的想法变成一份公开申请。

幽默的形式，降低开口的心理负担

02

用表态和讨论，接住表达

路过的人可以赞成、反对，也可以留一句理解、不同意见或善意调侃。「批准 / 驳回」是参与的趣味形式，生活怎么过仍由申请者自己选择。

被看见、被理解，也容得下不同声音

03

用后续，把故事讲下去

申请者可以回来分享后来发生了什么，让曾经回应过的人看到新进展。一次短暂的相遇，也能留下一个有头有尾的生活小故事。

申请 → 表态 → 讨论 → 后续故事

它不是普通的投票工具、传统匿名树洞，也不是替用户做决定的软件。项目的创新在于情绪表达方式、互动机制与后续反馈机制的结合。

从阅读，到聊聊自己的生活

轻量的生活观察，也可以成为表达的起点。

规则一份申请的一生

  1. 发起

    选主题、讲理由、定时限。自定义标题要先通过微信内容安全检测才会公开。

  2. 限时投票

    投票中的申请不显示赞成比例，避免带节奏；每人只能投一次，单份申请满 21 票封盘。

  3. 留下大家的看法

    到期自动出结果：有效票 ≥3 且非平票才分出批准 / 驳回，否则一律「未形成有效结果」——绝不假装 50% 也是个结论。

  4. 后续与围观

    截止后 7 天互动期：路人可以「后续表态」，申请人可以补「后续来了」故事线；神评论与默契度让围观也有参与感。

赞成与反对表达的是大家的看法，结果不替申请者做生活决定。讨论与后续故事，才让一次表态继续变成交流。

ENGINEERING技术栈与架构

小程序前端

原生 WXML / WXSS / JS，9 页面 4 标签，无第三方框架；三套主题走 CSS 变量设计系统。

Go 后端

标准库 net/http，唯一依赖 MySQL 驱动；约 40 个 JSON 接口，7300 行实现 + 4000 行测试。

MySQL 8

10 张业务表；投票以复合主键防重，写事务 + 行锁保证并发一致，keyset 游标分页。

微信云托管

Docker 多阶段构建、非 root 运行；小程序经 callContainer 内网调用，无公网域名。

几个值得展开的工程细节

以下工程数据核对于 2026-10-25，验证方式与范围见仓库文档。

  • 投票防重复：数据库复合主键 + 写序锁事务，40 并发投票实测只接受 21 票。
  • fail-closed 审核：内容安全接口故障时宁可拒绝发布，绝不放行未审内容。
  • 隐私优先：openid 用 HMAC 派生用户 ID、AES-GCM 加密存档，减少数据库泄露时的身份暴露风险。
  • 测试投入：后端 22 个测试文件 + 前端 102 项回归，测试代码约占后端 36%。

完整细节见仓库文档：docs/backend.md · docs/architecture.md

WHY为什么做这个

忙碌一天之后还想再干点活，休息时又觉得「是不是该更有意义一点」——这类小疲惫不需要解决方案，只需要有人回应一句「我懂」。

「今天能摆吗？」把日常小纠结写成一份公开申请。陌生人用表态与评论参与，申请者再讲讲后续，让原本只属于一个人的小情绪，变成一群人共同参与的小故事。

它由一位大学生独立完成：从产品定位、视觉设计，到 Go 后端、微信云托管部署与自动化测试。项目不追求改变谁的生活方式，只想让普通而疲惫的日常，多一个可以笑一笑的地方。

「我们不是在决定谁有资格休息，而是想让那些想休息的瞬间，也能成为一个值得分享的故事。」
